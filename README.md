# works-browser

D ドライブに整理した作品フォルダ群（Blender / ComfyUI の生成物を含む）を、ローカルで高速に閲覧するデスクトップアプリ。

- **Tauri v2**（Rust）+ React 19 + TypeScript + Vite
- フォルダ走査 → **SQLite 索引**（jwalk + rayon + rusqlite / WAL）
- 差分更新（追加・更新・削除）と `volume serial + file index` による**重複実体の検出**
- **ライブラリ画面**: 仮想スクロールの作品グリッド、インクリメンタル検索、種類 / ルート絞り込み、並び替え
- **タイムライン（日別）ビュー**（#81）: 更新日をローカル日付でまとめ、日付見出しを固定したまま新しい順にたどる
- **UI の土台**（#96）: Tailwind CSS v4 + shadcn/ui（Radix / nova）。**Gallery minimal** の
  デザイントークン（ダークのみ・紫 1 色）を `src/index.css` に集約。仕様は
  [docs/design.md](./docs/design.md)
- 画像 / 動画サムネイルの生成とキャッシュ（#19。長辺 512px WebP・rayon 並列）
- カード / タイルのホバーで**無音 5 秒プレビュー**（#46）
- **比較ビュー**（#71）: 2〜4 枚を同期ズームで並べ、2 枚なら**生成設定の差分タブ**（#74）
- **生成情報（プロンプト・モデル・シード等）の検索**（#60。FTS5 + LIKE。設定から索引）
- **生成情報の頻出語からタグ候補**（#79。作品詳細のタグ欄に「候補」チップ。クリックで付与）
- **ComfyUI 連携**（#73。workflow を ComfyUI で開く / API 形式で再実行）
- 動画はカスタムプロトコルでストリーミング再生（#5 で実装予定）

計画と設計は [PLAN.md](./PLAN.md)、走査・索引の設計は [docs/scan-design.md](./docs/scan-design.md)、
サムネイルの設計は [docs/thumb-design.md](./docs/thumb-design.md)、
画面のデザイントークンと構成は [docs/design.md](./docs/design.md)、
テストの層と実行方法は [docs/testing.md](./docs/testing.md) を参照。
性能の実測値（走査・サムネイル・クエリ）は [docs/perf.md](./docs/perf.md)。
開発は Issue 単位で進めます。

## 必要な環境（Windows）

| 必要 | バージョン / 備考 |
|---|---|
| [Rust](https://rustup.rs/) | stable（MSVC ツールチェーン）。`rustup default stable-msvc` |
| Visual Studio Build Tools 2022 | ワークロード「C++ によるデスクトップ開発」 |
| Node.js | 20.19 以上 / 22.12 以上（開発は 24 系で確認） |
| WebView2 Runtime | Windows 11 は標準搭載 |

Rust をインストールした直後のシェルでは PATH が通っていないことがあります。PowerShell なら次を実行するか、`%USERPROFILE%\.cargo\bin\` を直接指定してください。

```powershell
$env:Path += ";$env:USERPROFILE\.cargo\bin"
rustc -V
cargo -V
```

PowerShell で `npm.ps1` が実行ポリシーにブロックされる場合は `npm.cmd` を使ってください。

## セットアップ

```powershell
npm install
```

Rust をビルドする前に、ffmpeg の sidecar を 1 回だけ配置してください
（`bundle.externalBin` の存在チェックがあるため、無いと `cargo check` も失敗します）。

```powershell
powershell -ExecutionPolicy Bypass -File scripts/fetch-ffmpeg.ps1
# 別の ffmpeg を使う場合
powershell -ExecutionPolicy Bypass -File scripts/fetch-ffmpeg.ps1 -Source C:\path\to\ffmpeg.exe
```

配置先は `src-tauri/binaries/ffmpeg-x86_64-pc-windows-msvc.exe`（`.gitignore` 済み）。
動画サムネイルを使わない場合でも、ビルドにはファイルが必要です。

## 走査と索引の使い方

1. `npm run tauri dev` でアプリを起動する
2. 右上の「ルート」を押すと **OS のフォルダ選択ダイアログ** が開く。フォルダを選ぶ
   （複数選択可）と、作品の単位（深さ）を選ぶステップが出る（既定は第 1 階層）。
   「追加してスキャン」でルート登録と索引作成が一度に始まる
3. エクスプローラからフォルダをウィンドウへ **ドラッグ&ドロップ** しても追加できる。
   ドラッグ中は全画面オーバーレイが出て、ファイルを落とした場合は
   「フォルダをドロップしてください」と案内する
4. ライブラリ画面に **作品数 / ファイル数 / 合計サイズ / 最終走査** と作品グリッドが出る

> パスの手入力は不要です。コピーしたパスを貼りたいときだけ「ルート管理」→
> 「詳細（パスを直接入力）」を開いてください。

### ルート追加（#25）

| 導線 | 動き |
|---|---|
| **ルート**（ヘッダー） | `tauri-plugin-dialog` の `open({ directory: true, multiple: true })` でフォルダ選択（塗りの主要操作） |
| **ドラッグ&ドロップ** | Tauri の `onDragDropEvent`。フォルダだけを受け付け、複数可 |
| **最近追加したフォルダ** | 追加に成功したパスを最大 10 件 DB（`meta.recent_roots`）に保存して候補表示 |
| **候補** | `D:\ComfyUI\output` / `D:\Projects\Blender\03_generated` など実在するもの |
| **ドライブ** | `GetLogicalDrives` で列挙した `C:\` `D:\` … をチップで選択 |
| **詳細（パスを直接入力）** | 既存のテキスト入力を折りたたみ。コピペ用途 |

追加前の検証（`inspect_root_paths`）で次を警告します。警告が出ても「追加してスキャン」で
続行できます（追加ボタン自体が確認になる）。

- 存在しないパス / フォルダ以外（ファイル）は追加不可
- 権限が無く `read_dir` できないフォルダはエラー（追加時にメッセージ）
- 既に登録済みのフォルダ（同じ実体パス）は深さだけ更新
- `volume serial + file index` が一致する別ルート（junction など）は重複として警告
- `D:\` などのドライブ直下、`C:\Windows` / `Program Files` などのシステムフォルダは警告

### デザイントークンと画面構成（#96）

ライブラリのクロームは **Gallery minimal**（余白広め・作品が主役・クロームは抑制）に統一しました。
テーマは**ダークのみ**、アクセントは**紫 `#7c6cff` の 1 色**だけです。値は
`src/index.css` の `:root` に 1 箇所だけ定義し、画面側は `var(--xxx)` を参照します。
トークン表・コントラスト比・画面構成の詳細は [docs/design.md](./docs/design.md)。

| 項目 | 値 |
|---|---|
| 余白 | 4 / 8 / 12 / 16 / 24 / 32 / 48 |
| 角丸 | 8（操作系）/ 12（カード）/ 16（パネル） |
| 背景 | bg `#0a0a0c` / surface `#111116` / raised `#17171d` |
| 罫線 | `rgba(255,255,255,.07)` / 強 `rgba(255,255,255,.12)` |
| 文字 | primary `#ededf2` / secondary `#a4a4b3` / tertiary `#7c7c8c`（ラベルのみ） |
| アクセント | 紫 `#7c6cff`（選択・フォーカス・主要操作だけ） |
| 文字サイズ | 11（フィルタ節ラベル）/ 12 / 13 / 15 / 21 / 32 |
| 表示用フォント | 21px 以上は `Segoe UI Variable Display` → `Segoe UI`、字間 `-0.02em`（#108） |
| 行間 | 本文 1.5 / 見出し 1.3 |
| 動き | 160ms `cubic-bezier(.2,.7,.3,1)`、`prefers-reduced-motion` で無効 |
| フォーカス | 2px リング + offset 2 |

- **ヘッダー（56px・1 段）**: ブランドマーク（右上に 2px のアクセントドット）+
  「ライブラリ」21px/600（表示用フォント）。統計は
  `作品 24 · ファイル 96 · サイズ 1.2 GB · 最終走査 2026-11-27` の 12px tabular 1 行
  （未走査なら「最終走査 未走査」）。
  右は 32px のアイコンボタン（サムネ表示・重複整理・シールド設定・再読み込み・ルート管理・
  設定。**すべてツールチップ付き**）と、塗りの主要操作「ルート」1 つ
- **ツールバー（48px・1 段）**: 検索（320〜420px）/ フィルタ（適用件数バッジ + ポップオーバー）/
  並びメニュー + 昇降アイコン / 右端は**件数 + サムネトグル + 表示切替セグメント**のクラスタ。
  サムネトグルは `Eye` / `EyeOff` + 「サムネ」のラベル付き（`Ctrl+Shift+H`、詳細と状態を共有）。
  適用中のフィルタだけを、下に削除可能なチップで出す。フィルタの選択は紫の塗り + 黒文字で統一
- **サイドバー（240px）**: 節見出し 12px / `.08em` / secondary、行 32px、件数は右寄せ tabular。
  ルートが無いときは**オンボーディング 1 ブロックだけ**（説明 1 行 + 「ルートを追加」）。
  スマートフォルダの節・空状態はルートがある場合だけ出す
- **作品詳細（#99 / #108）**: 題名 32px/650（表示用フォント）・メタ 1 行・評価の独立行の
  3 層ヘッダ。お気に入り / 開封数 / ルート名もメタ 1 行へ統合し、タグだけチップを残す。
  右上は「開く」「フォルダ」の 2 つだけで、削除などは `⋯` メニューへ。ツールバーは 1 段
  （種類セグメント / 並びメニュー / 昇降 / 右端に件数とサムネ表示）。ファイルカードは
  4:3・角丸 12・名前 1 行・メタ 2 行（#98 の規則）
- 1280×800 で折り返さず、12px の文字はすべてコントラスト 7:1 以上（実測表は
  [docs/design.md](./docs/design.md)）。設定は右下の固定ピルをやめ、ヘッダーのアイコンへ移動

### 作品カードとグリッド（#98）

サムネイル非表示が既定なので、**画像なしのカードが基本形**です。カードは 4:3 の
カバー + 2 行のメタで構成し、ホバー / 選択 / フォーカスだけを静かに変えます。
寸法は `src/library/gridMetrics.ts` に集約しています。

- **カード**: カバー **4:3 固定**（`object-fit: cover`、角丸 12）。メタは
  「題名 15px / 600（1 行省略）」+「`N ファイル · サイズ · 日付` 12px / tabular」の 2 行。
  ルート名は余白を優先してカードに出さず、ツールチップと `aria-label` に含める
- **プレースホルダ**: 画像なしのカードは「暗い空箱」ではなく、タイトルから生成した
  タイポグラフィック・カバー。ハッシュで色相を決めた 8% の面に、先頭 1〜2 文字
  （日本語 1 文字 / 英数字 2 文字）を 56〜72px・7% の白で置く。同じ作品は常に同じ見た目
- **種類バッジ**: 写真の左上に **14px のアイコンのみ**（白 60% + 落ち影、#108）。
  ピル・背景・文字は使わない。画像なしのときは従来どおりアイコンのみ（20px）。
  どちらもツールチップ / `aria-label` で種類を出す
- **ホバー**: 背景を 1 段明るく（`surface` → `raised`）し、開く操作と選択チェックを
  **160ms** でフェードイン。フォーカスは 2px リングだけで、背景や枠は変えない
- **選択**: チェックボックスの塗りに加えて、**アクセント 2px の内側リング + 10% の
  背景ティント**。チェックが見えていなくても選択中と分かる
- **グリッド**: 列数 **3〜6**（内側幅 1560 / 1240 / 880 が境界）、外側余白 24、間隔 16。
  **1280×800 で 4 列、1920×1080 で 6 列**（#108 で余白・列数を再確認）。カード高さは
  4:3 のカバー + メタ 66px で、幅に追従して仮想スクロールの行送りも測り直す
- ホバー動画プレビュー（#46）、2×2 モザイク（#21）、ドラッグ&ドロップ（#57）、
  `j` / `k` のフォーカス移動（#71）はそのまま動きます

### 状態・空状態・モーション（#100）

空状態は「控えめなアイコン + 短い説明 + 次の行動 1 つ」に統一しました
（`src/library/EmptyState.tsx`）。ルート無し / スマートフォルダ無し / 検索 0 件 /
サムネイル未生成の 4 種で、サムネ未生成はメイン上部の notice として出ます。

- **読み込み中**: 4:3 のカバー + メタ 2 行を保ったスケルトンを **3 列 × 2 行**で表示。
  **200ms 未満**の読み込みでは出さない（`useDelayedVisible`。ちらつき防止）
- **フォーカス**: すべての操作要素が `:focus-visible` の **2px / offset 2**。
  `outline-none` に負けないよう、ルールは `@layer` の外に置いています
- **キーボード**: 一覧で `Enter` → 詳細、`Esc` / `Alt+←` → 戻る。アイコンボタンは
  `aria-label` 必須（ダイアログの `×` も「閉じる」）
- **モーション**: ホバー / 選択 / ダイアログを **160ms** に統一。ダイアログは
  0.98 → 1 の拡大 + フェード。`prefers-reduced-motion: reduce` で無効
- **ダイアログ**: 設定・`?` ヘルプ・重複整理・比較ビューのヘッダー / 余白 / 文字サイズを
  同じトークン（題名 15px / 600、説明 12px、余白 24）に揃えました

### 生成情報（メタデータ）の検索（#60）

画像・動画に埋め込まれた生成情報（プロンプト・ネガティブ・モデル・LoRA・シード等）を
索引して、作品ブラウザから検索できます。

1. 設定 → **「生成情報を索引する」** を押す（未索引のファイルだけを 500 件ずつ読みます。
   進捗は `meta://progress`、完了後に**メタデータ付与率**が更新されます）
2. ライブラリの「フィルタ」ポップオーバーで **「生成情報も検索」** を ON にする（既定 OFF）
3. 検索語がプロンプト・モデル名・LoRA などに当たった作品だけが表示されます
4. 作品詳細のファイル一覧では、生成情報を持つファイルに **`meta` バッジ**が付きます

抽出元は PNG のテキストチャンク（A1111 `parameters` / ComfyUI `prompt`）、JPEG / WebP の
EXIF `UserComment`、同じフォルダのサイドカー（`<name>.worksmeta.json` / `<name>.json` /
`<name>.txt` / `manifest.jsonl`）、動画の ffmpeg `ffmetadata`（`comment` / `prompt`）です。
結果は `files.meta_json` に正規化して保存し、ファイルの `mtime` が変わったときだけ再抽出します。

- 検索は `files_meta_fts`（FTS5: prompt / negative_prompt / model / loras）を使い、
  ヒットが無ければ生 JSON の `LIKE` に落ちます（シード値や部分一致はこちらで拾います）
- 壊れた JSON が混ざっていても検索は落ちません（JSON としてパースしないため）
- メタデータの無いファイルは「抽出済み・情報なし」として空文字でキャッシュし、毎回は読み直しません

### タグ候補（#79）

作品詳細のタグ欄（「タグ」ダイアログ）の下に、その作品の生成情報に**よく出てくる語**を
**「候補」チップ**として表示します。押すとその語をタグとして付与します（同名のタグが
ライブラリにあればそれを使い、無ければ既定色で作ってから付与）。

- 対象は `files.meta_json` の **prompt / negative_prompt / loras / model** だけです
- 分割は**空白・カンマ・改行**。正規化は**小文字化 / 全角→半角 / `_`・`-` を空白 /
  連続空白を 1 つ**（`(word:1.2)` の重みは語だけ取ります）
- 除外する語:
  - 品質系・ネガティブの定型語（`masterpiece` / `best quality` / `highres` / `absurdres` /
    `simple background` / `worst quality` / `jpeg artifacts` など）
  - 1〜2 文字の語（`red` は候補、`a` / `ab` は候補にしない）
  - **長すぎる語（24 文字超）**。日本語は空白区切りが無く句読点なしの長文が 1 語になりやすい。
    タグの 40 文字制限より十分小さい 24 文字で切るので、候補を押して付与がエラーにならない
  - 数字だけの語（`1.0` のような小数も除外）
  - **既にその作品に付いているタグと同じ語**（表記ゆれは同じタグとして扱う。大文字小文字・
    全角半角・`_` / `-` と空白を同一視するので、`red_dress` と `red dress` は別物にならない）
- 並びは**頻度順**（同数は名前順）で、既定は上位 **20 件**です。`count` は
  「その語を含む**ファイル数**」で、同じファイル内に何度出ても 1 と数えます

#### 仕組み

- 集計は **Rust 側**（`src-tauri/src/tagsuggest.rs` の純関数 + `db::tag_suggestions`）。
  `files.meta_json` は #60 でキャッシュ済みなので、**実ファイルは読み直しません**
- 候補の長さ上限は `MAX_CANDIDATE_CHARS`（24 文字）。既存タグとの比較は `tag_key`
  （候補と同じ正規化）を通すため、`Red_Dress` / `red dress` / 全角表記も同じタグです
- 1 リクエストでその作品の全ファイルを集計するため、UI から全作品を走査しません
- 生成情報が無い作品（`meta_json` が空）や、除外後に語が残らない作品は**空配列**を返し、
  UI は「候補」の欄自体を出しません
- 複数作品をまとめてタグ付けするとき（ライブラリの選択バー）は候補を出しません
  （付与後に候補を取り直すため、付けた語はチップから消えます）

#### 確認用

- `cargo test` … 正規化 / トークン化 / 品質系の除外 / 長すぎる語の除外（日本語・英語）/
  タグ名の正規化一致（`_` / 空白 / 全角）/ ファイル単位の重複除去 / 頻度順 /
  既存タグの除外 / 生成情報なしで空
- `npx vitest run tests/tag-suggestions.test.tsx` … チップの表示・クリックで付与・
  同名タグの再利用・空のとき非表示・複数作品では出さない

### ComfyUI 連携（#73）

画像（PNG）に埋め込まれた ComfyUI の生成情報から、**workflow を ComfyUI で開く** /
**同じ設定で再実行する** ことができます。実データ `D:\ComfyUI\output` の PNG 34 枚は
`tEXt:prompt`（API 形式）だけを持ち、`workflow`（UI 形式）は 0 件だったため、
**API 形式を主経路**にしています。

#### 設定

1. 設定 → **ComfyUI 連携**
2. **URL** に ComfyUI のアドレス（既定 `http://127.0.0.1:8188`）を入れる
3. **workflows** に ComfyUI の `user/default/workflows` を指定する（workflow を保存して開く場合）
4. **接続確認** … 入力中の URL を保存してから `GET /system_stats` を叩き、結果を表示します

`http` のみ対応です（TLS を同梱しないため）。`https` の URL は接続確認で理由を表示します。

#### 画像の生成情報パネル（ライトボックス）

画像を開き、右上の「生成情報」をオンにすると、パネルの下部に **ComfyUI へ** の操作が出ます。

| 元データ | 操作 | 動き |
|---|---|---|
| `workflow`（UI 形式）あり | **ComfyUI へ** | 設定の workflows フォルダへ `<name>.json` として保存し、`http://<URL>/?workflow=<name>` を既定のブラウザで開く |
| `workflow` なし・`prompt`（API 形式）あり | **ComfyUI へ** | API JSON をクリップボードへコピーし、「ComfyUI に貼り付けて読み込んでください」と表示（コピーできなければ選択用のテキスト欄を出す） |
| どちらも無い | （ボタンを出さない） | 「この画像には ComfyUI の workflow / API プロンプトがありません」 |

workflow のファイル名は元画像の拡張子を除いた名前です（Windows の禁止文字は `_` に置換）。
同じ名前の workflow は上書きします。

#### この設定で再実行

`prompt`（API 形式）がある画像では **この設定で再実行** が出ます。

1. ボタンを押すと確認ダイアログ（ComfyUI のキューに入る旨）を表示
2. 「キューに追加」で `POST {url}/prompt` に
   `{"prompt": <API JSON>, "client_id": "<uuid>"}` を送信
3. 成功すると `prompt_id` を表示。失敗時は日本語で理由（接続不可 / HTTP 4xx / JSON 不正）を表示

- HTTP は Rust 側（`ureq`）で行い、UI は **`file_id` だけ**を渡します。接続先は `config.json` の
  `comfy_url` のみで、UI から任意の URL は受け取りません
- 再実行は ComfyUI 側にもう一度生成させる操作です。実行前に確認ダイアログを必ず出します
- **実機の ComfyUI への送信は未確認**です（GUI を起動しない `cargo test` / `npm run test:unit` のみ）

- `cargo test` … PNG の `workflow` + `prompt` / `prompt` のみ / `workflow` のみ / 壊れた JSON /
  どちらも無い、URL の組み立てと検証、エラー文言、workflow の保存
- `npm run test:unit` … `workflow` / `api` / `none` の分岐と「再実行」の可否

### 重複・類似の整理（#67）

AI 生成フォルダに増えがちな「まったく同じファイル」と「ほぼ同じ絵」をまとめて片付けます
（Eagle の重複スキャン / Hydrus の similar files と同じ考え方）。

1. ヘッダーの **重複整理アイコン**（`CopyCheck`。ツールチップ「重複整理」）を開く
2. 初回だけ **「解析する」** を押す（バックグラウンドで解析。進捗は `dupes://progress`、
   途中で「解析を中止」しても、そこまでの結果は DB に残ります）
3. **完全一致**（内容の SHA-1 が同じ）と **類似**（dHash 64bit のハミング距離、既定 8）を切り替えて確認
4. グループごとに「残す 1 枚」（画素数 → バイト数 → 新しい順）が提案される。
   サムネイルをクリックすると別の 1 枚をキーパーに指定できます
5. **「他をゴミ箱へ」** でキーパー以外を既存の削除フローへ（確認 + 5 秒 Undo）

- 類似判定は**グループの代表との距離**だけで行うので、連鎖で無関係な画像が混ざりません
- 解析結果は `files.content_hash` / `files.dhash` にキャッシュし、元ファイルの `mtime` / サイズが
  変わったときだけ再計算します（動画は完全一致のみ）
- 初回の解析はファイル数に比例します（画像 1 枚あたり数十 ms。SSD で数万枚なら数分）

### 選択と削除（#15）

複数選択した作品・ファイルを、**確認ダイアログ → ゴミ箱へ移動 → 5 秒間の Undo** の流れで
削除します。恒久削除は `Shift+Delete`（または確認ダイアログのチェック）を明示したときだけです。

#### 操作と画面

| 操作 | 動き |
|---|---|
| 選択バーの「削除」/ `Delete` | 確認ダイアログ（件数・合計サイズ・「ゴミ箱へ移動します」） |
| `Shift+Delete` | 同じ確認ダイアログ。恒久削除にチェック済み。赤字で「元に戻せません」 |
| 確認ダイアログの「ゴミ箱へ移動」 | ゴミ箱へ移動し、5 秒間「取り消す」トーストを表示 |
| 確認ダイアログの「完全に削除」 | ゴミ箱を使わず `fs::remove_file`（Undo なし） |
| 作品詳細の「ゴミ箱へ」 | その作品の全ファイルを対象にする（作品 id を Rust で展開） |

- **削除中**: 確認ボタンを無効化し、`delete://progress`（done / total）で進捗バーを更新。
  「中止」で `cancel_delete` を呼ぶ。成功済みのファイルは確定し、残りを止める
- **二重実行の防止**: UI の `deleting` 状態と Rust 側 `AppState.deleting`（`AtomicBool`）の両方で弾く
- **結果**: 成功件数と合計サイズを出し、失敗があれば理由ごとにまとめて「N 件: 理由」で表示

#### ゴミ箱と Undo

- 既定は `trash` crate（Windows は `IFileOperation` + `FOF_ALLOWUNDO`）で**即座にゴミ箱へ移動**する
  （削除を遅延させない）。移動後にゴミ箱を列挙し、元のパスが一致する項目を Undo 用に保持する
- 画面下に **5 秒のカウントダウン付きトースト**と「取り消す」を表示。「取り消す」は
  `os_limited::restore_all` で元の場所へ戻し、削除前のスナップショットから
  `works` / `files` の行を作り直す（再生位置は復元しない）
- トーストが消えた後（**5 秒経過後**）もファイルはゴミ箱に残るため、
  **エクスプローラの「ごみ箱」からいつでも復元できる**（無効になるのは `undo_delete` の
  トークンだけで、次の削除で置き換わる）
- 同名ファイルが既にある等でアプリからの復元に失敗した場合は、その理由とあわせて
  **「エクスプローラのゴミ箱から復元してください」**と案内する
- `Shift+Delete` の恒久削除はゴミ箱に入らず Undo できないため、確認ダイアログで赤字警告する

#### 安全策と後始末

- UI は **`files.id`（作品は `work_ids`）だけ**を渡す。パスは Rust が DB から引き、任意パスを渡せない
- 削除前に登録ルートの実体パスへ `canonicalize` して照合し、**ルート外を指す相対パス（`..`）や
  ルート外へ解決されるパスは拒否**。シンボリックリンク / ジャンクション（再解析ポイント）自体も拒否し、
  リンク先は削除しない
- 読み取り専用・使用中・権限なしはスキップし、`{ id, reason }` で返す（DB の行も残す）
- 実ファイルの削除に成功したものだけ `files` から削除。空になった `works` は削除し、残った作品は
  `file_count` / `total_bytes` / `mtime` / `kind` / カバーを再計算する
- サムネイルキャッシュ `thumbs/<sha1(real_path + rel_path)>.webp` も削除する
- 50 件ずつ `IFileOperation` にまとめ、失敗したチャンクだけ 1 件ずつ再実行して理由を特定する

### 作品の移動（ドラッグ&ドロップ・#57）

作品カードを左サイドバーのルート行へドラッグ&ドロップすると、**実ファイルのフォルダ**を
そのルートへ移動して索引を付け替えます。削除と同じく、失敗するとデータを失う操作なので
確認と安全策を必須にしています。

#### 操作と画面

| 操作 | 動き |
|---|---|
| 作品カードをルート行へドラッグ | ドロップできるルートが点線で強調され、ホバー中の行はアクセント色でハイライト |
| ドロップ | `inspect_move` で計画を作り、確認ダイアログを開く（この時点では実ファイルに触れない） |
| 確認ダイアログ | 移動先のフルパス・ファイル数・合計サイズ・**同一 / 別ボリューム**を表示 |
| 「移動する」 | 移動を実行。進捗（移動済み / 総バイト）と「中止」を表示 |
| 完了（同一ボリューム） | 画面下に **5 秒間**「元に戻す」を表示（`undo_move`） |
| 完了（別ボリューム） | Undo なし。移動元・移動先の一覧を再取得して反映 |

- 同じルートへ落としても何もしません（ドロップ不可の見た目にします）
- 5GB 超または別ボリュームのときは、確認ダイアログに「時間がかかります」と明示します
- 完了後は `onRootsChanged` → `list_roots` / `find_works` を読み直し、移動元・移動先の
  両方の件数と一覧を更新します

#### 安全策

- UI は **`work_id` と移動先の `root_id` だけ**を渡す。パスは Rust が DB から引く
- 移動元は登録ルートの内側に解決されることを `canonicalize` で確認し、`..` や
  ルート外を指す相対パスは拒否
- 移動元・移動先のシンボリックリンク / ジャンクション（作品内に含まれるものも）は拒否
- 移動先ルートが存在しない（ドライブ未接続）・フォルダでない・読めない場合は拒否
- 移動先の同名フォルダは**上書きせず** `"name (2)"` にリネーム（DB に同名がある場合もずらす）
- **同一ボリューム**は `fs::rename` で一瞬。**別ボリューム**は
  **コピー → 全ファイルの存在とサイズを検証 → 移動元を削除**
- コピー中にキャンセルした場合は、コピー先の部分データを削除してから終了
- 移動元の削除に失敗した場合は、コピー先に完全なコピーがあることを理由付きで報告
- 索引を更新できなかった場合は rename を戻す（別ボリュームはその旨と再スキャンを案内）
- 索引更新は `works.root_id` / `works.rel_path` / `works.title` と
  `files.rel_path`（作品パス接頭辞の差し替え）を 1 トランザクションで行う

#### 確認用

- `cargo test` … 一時ディレクトリで「移動 → 索引が移動先に付く」「同名は (2) になる」
  「無効ルートへは拒否」「ジャンクションは拒否」「キャンセルで部分データが残らない」
  「同一ボリュームの Undo で元に戻る」「別ボリューム（強制）のコピー + 削除」
- `npm run test:unit` … ドラッグの dataTransfer（作品 id）の読み取り
- GUI での実機確認（D&D・確認ダイアログ・進捗・Undo）はオーナーが行います
  （エージェントは `npm run tauri dev` を起動しません）

### 表示モードとホバープレビュー（#21）

ライブラリは **作品 / ファイル** の 2 モードと、どちらにも被さる **サムネ非表示** トグルで
構成します。モードとトグルは `config.json` に保存し、次回起動時に復元します。

| モード | 内容 | キー |
|---|---|---|
| **作品**（既定） | 作品カードのグリッド。カバー（または 2×2 モザイク）+ タイトル + 本数・サイズ・日付 | `Alt+1` |
| **ファイル** | 作品を無視して `files` を直接グリッド表示。左上に所属作品名、下にファイル名・長さ・サイズ・日付 | `Alt+2` |
| **タイムライン** | 作品を更新日のローカル日付ごとにまとめた日別セクション（#81） | `Alt+3`（`Ctrl+Shift+T` も可） |
| **サムネ非表示** | 独立トグル。作品 / ファイルどちらのモードでもコンパクトなリストになり、タイムラインではサムネイルを要求しない。ツールバー右端の `Eye` / `EyeOff` + 「サムネ」でも切り替えられる（#120） | `Ctrl+Shift+H` |

> **#88**: 以前は表示モードが `Ctrl+1` / `Ctrl+2` で、ルート絞り込みの `Ctrl+1..9` と
> 二重発火していました。表示モードは `Alt+1` / `Alt+2` / `Alt+3` に移し、`Ctrl+1..9` は
> ルート絞り込みだけが使います（`Ctrl+1` でモードは変わりません）。

#### 戻ったときの絞り込みとサムネトグル（#120）

作品詳細へ移動すると `LibraryView` はアンマウントされるため、絞り込みは
`App` の履歴（`LibrarySnapshot.filters`）へ写してから離れます。

- 復元する項目: ルート / 検索語 / 種類 / タグ / 最低評価 / お気に入り / 生成情報も検索 /
  並び順 / 昇順・降順 / ファイルモードのルート
- 詳細から戻ると、選んでいたルートが「すべて」に戻らず、チップとサイドバーの
  `aria-current` もそのまま復元されます
- 「すべて」や空検索を選んだあとは、その**新しい状態**が履歴に写るので、
  古い検索語やルートが復活しません
- サムネトグルは作品 / ファイル / タイムライン / 作品詳細の全ツールバー右端に表示し、
  ヘッダーの目アイコンと同じ `useThumbnailVisible` を共有します（#121 で
  `ThumbnailToggle` の `compact` / `labeled` に共通化）
- 全体非表示中は作品カード右上（チェックの左隣・8px 間隔）の目アイコンで、
  その作品のカバー（4 枚揃っていればモザイク）だけ一時表示できます。全体トグルを
  切り替えるとファイル / 作品の個別状態はまとめてリセットされます（#121）
- 目アイコンは通常は透明で `pointer-events: none`。カードの hover / focus-within
  （とボタン自身の `focus-visible`）でだけ出し、タッチ環境（`@media (hover: none)`）
  では常時表示のままにします（#5）。チェックボックスの hover 表示は従来どおりです
- 回帰テスト: `tests/library-filter-restore.test.tsx`（ルート選択 → 詳細 → 戻る /
  検索語 → 空検索 → 詳細 → 戻る）、`tests/library-thumb-toggle.test.tsx`
  （`aria-pressed`・ラベル・全モード・詳細との同期）、`tests/work-card-reveal.test.tsx`
  （作品単位の個別表示・全体トグルでのリセット・タイムライン）、
  `tests/library-filters.test.ts`（復元用の純関数）

#### サムネ非表示

- 画像リクエスト **0 件**（`convertFileSrc` を呼ばない）、`<img>` もレンダリングしない
- ホバープレビューは無効。`thumbs://progress` の購読と `generate_thumbs` の自動キックも止める
- Rust 側でも `generate_thumbs` が `config.json` を見て生成をスキップするため、
  `%LOCALAPPDATA%\works-browser\thumbs` のファイル数は増えない（`thumbs` のテストで担保）
- 表示は種類アイコン + 名前 + サイズ + 長さ + 日付 + 作品名の仮想スクロールリスト
  （作品モードでは本数、ファイルモードでは作品名と長さを出し分け）
- 全体非表示中だけ、ファイルカードの「このファイルだけ表示」と、作品カードの
  「この作品のサムネイルを表示」（右上・チェックの左隣）が出ます。個別状態は
  全体トグルを切り替えるとリセットされ、保存されません（#52 / #121）
- その目アイコンは hover / キーボードフォーカスのときだけ表示し、普段は
  `pointer-events: none` でノイズにしません。タッチ環境（`@media (hover: none)`）
  だけは常時表示です（#5）

#### ファイルモード

- クエリ: `list_files(limit, offset, sort, kind, root_id, query)`（`files` JOIN `works`）
- 並び順: 更新日 / 名前 / サイズ / 長さ（動画のみ。尺の無い画像は末尾）
- **昇順 / 降順**: 「並び」メニューの隣のアイコンで切り替えます。キーを変えると既定の向き
  （更新日・サイズ・長さは新しい / 大きい / 長い順、名前は昇順）に戻ります（#87）
- 絞り込み: 動画のみ / 画像のみ / ルート / 生成情報も検索（「フィルタ」ポップオーバー）/
  ファイル名・パスの部分一致（検索欄）
- 仮想スクロールは既存の `@tanstack/react-virtual` を流用（600 件ずつ）。
  ページ送りは `LIMIT/OFFSET` とキーセット（`after_id`）の両方に対応（#50）
- スキーマ v3 で `files` の `mtime` / `name` / `bytes` / `duration_ms` に索引を追加
- 本体クリックで作品詳細（#5）を開く（ダブルクリック / Enter も同じ）。選択は右上の
  チェックボックス（作品カードと同じ操作。Ctrl / Shift はチェック上のみ。#27）

#### タイムライン（日別・#81）

作品の `mtime` を**ローカル日付**に落として日別にまとめ、新しい日から順に並べます。
ツールバー右端の **タイムライン**、`Alt+3`、または従来の `Ctrl+Shift+T` で切り替えます。

- 見出しは **`2026-11-26（木）・12 件`** の形。スクロール中はその日の見出しが
  上端に固定（sticky）され、次の日に入ると差し替わります
- セクション内は `WorkCard` をそのまま並べた折り返しグリッド。ホバーで少し拡大し、
  クリック（`Enter` も同じ）で作品詳細を開きます
- **遅延読み込み**: 既存の `find_works` を `sort=mtime` / 降順で 600 件ずつ読み、
  届いた分から日付グループに足します。**追加のクエリは増やしていません**。
  描画も `@tanstack/react-virtual` で可視行だけを DOM に置きます
- サムネ非表示（既定 OFF）のときは `WorkCard` が `convertFileSrc` を呼ばず、
  `<img>` も出しません（#21 の方針をそのまま）
- 日付のグルーピングは `src/lib/timeline.ts` の純関数（`localDateKey` /
  `groupWorksByDay` / `timelineHeading`）。`toLocaleDateString` は使わず、
  `Date` のローカル getter だけで `YYYY-MM-DD` を作るため、タイムゾーンで
  日付がずれません（テスト: `tests/timeline.test.ts`）
- 作品 ↔ ファイル ↔ タイムラインを切り替えても、スクロール位置と選択はモードごとに
  保たれます（タイムラインの選択は作品モードと同じ選択を共有）
- `Ctrl+3` は**ルートの絞り込み**（#55）が使うため、タイムラインは `Alt+3` と
  `Ctrl+Shift+T` で切り替えます（#88 で表示モードを `Alt+1..3` に移動）。表示モードは
  作品 / ファイルと同じく `config.json`（`view_mode: "timeline"`）に保存し、
  次回起動時に復元します

#### ホバープレビュー（作品モード）

- カードに **600ms** ホバーすると、先頭 4 ファイルのサムネイルを **800ms 間隔**で切り替える
- 先読みは**同時 1 カード・最大 4 枚**。別のカードへ移ると前の先読みは破棄する
- マウスが外れたらカバー（またはモザイク）に戻る
- `prefers-reduced-motion: reduce` とタッチ環境（`maxTouchPoints` / `pointer: coarse`）では切り替えない
- サムネ非表示中は先読みもしない（`useHoverPreview` の `enabled = false`）

#### ホバー動画プレビュー（#46）

- 動画のカード / ファイルタイルに **600ms** ホバーすると、その場で **無音 5 秒**のプレビューを再生する
  - 再生位置は動画の **10%** 地点。5 秒経過するかマウスが外れたら止めてサムネイルに戻す（ループしない）
- **常にミュート**（`muted` 固定）・`playsInline`・`preload="none"`。`src` は `wbm` プロトコルの
  Range 配信なので、全体を読み込まずに再生を始める
- `<video>` はアプリ全体で **1 つだけ**作り直さずに使い回す（同時再生は 1 本）。
  停止時は `pause()` → `src` の解除 → `load()` でリソースを解放する
- サムネ非表示 / プライバシーシールド中 / ベンチモード / `prefers-reduced-motion: reduce`
  では無効。画像のカードと、再生に失敗したカードはサムネイルのまま表示する
- 作品モードは**動画を含む作品**（カバーは動画優先）、ファイルモードは動画ファイルが対象

#### カードのモザイク（任意）

`find_works` は各作品の先頭 4 ファイルのサムネイルパス（`preview_thumbs`）も返します。
4 枚揃っていればカバー 1 枚の代わりに **2×2 モザイク**を表示し、1 枚でも読み込みに
失敗したらカバー 1 枚へフォールバックします。サムネ非表示中は使いません。

#### 設定ファイル

| 項目 | パス |
|---|---|
| 表示設定・シールド設定 | `%APPDATA%\works-browser\config.json` |
| 任意 | 環境変数 `WORKS_BROWSER_CONFIG` で上書き（検証用） |

中身は次のとおりです（#22 の項目は下の「プライバシーシールド」を参照）。

```json
{
  "view_mode": "works",
  "thumbnails_visible": true,
  "shield_hotkey": "Ctrl+Shift+P",
  "shield_hold_ms": 1000,
  "shield_start_hidden": false,
  "shield_appearance": "files",
  "watch_enabled": true,
  "watch_exclude": [],
  "watch_network_drives": false,
  "index_mpeg_ts": false,
  "comfy_url": "http://127.0.0.1:8188",
```

壊れた JSON や未知のモードは既定値（作品 / サムネ表示 / `Ctrl+Shift+P` / 1 秒 /
ファイル名リスト）に丸めます。起動直後のちらつきを避けるため、同じ内容を localStorage
（`works-browser.library-prefs`）にも写しています。

`index_mpeg_ts` は `.ts` を MPEG-TS として索引するか（既定 `false`）。TypeScript の
ソースを動画として拾わないよう、通常は `false` のまま使います（#39）。

### プライバシーシールド（#22）

家族などが画面を覗いたときに、**1 キーで画像・動画・サムネイルを隠す**緊急用の画面です。
#21 のサムネ非表示（`useThumbnailVisible`）をそのまま被せ、作品 / ファイルモードの
絞り込み・選択・スクロール位置は保ったまま、`<img>` を 0 件にします。

#### 発動と復帰

| 操作 | 動作 |
|---|---|
| `Ctrl+Shift+P`（グローバル） | アプリが非アクティブでも発動。シールド中は **長押し**で解除 |
| `Esc` を長押し | アプリ内で発動（既定 1 秒。設定で 0.5 / 1 / 2 秒） |
| オーバーレイの「戻す」 | すぐに解除 |

- グローバルホットキーは Rust の `tauri-plugin-global-shortcut` で登録し、
  `shield://hotkey`（pressed / released）を UI に送ります。解除の長押し判定は UI 側です
- 発動中は「隠しています」とは書かず、**汎用的なファイル名だけの作業アプリ風画面**を
  最前面（`z-index: 200`）に事前マウントしたまま表示します。実際の作品名・ファイル名は出しません
- 解除すると、スクロール位置（グリッド / リストで高さが変わるため割合で保存）と
  動画の再生位置・再生状態・ミュート状態へ戻ります

#### 発動中の動作

| 対象 | 動作 |
|---|---|
| 画像・サムネイル | #21 のコンパクトリストへ切り替え、`<img>` も画像リクエストも **0 件** |
| 再生中の動画 | 発動の瞬間に `pause()` + `muted = true`。解除時に元の状態へ戻す |
| サムネイル生成 | UI の購読を外し、実行中の生成も `cancel_thumbs` で止める |
| ウィンドウタイトル | Rust から `works-browser` のみに変更 |
| Alt+Tab / タスクバーのプレビュー | Windows の `DWMWA_EXCLUDED_FROM_PEEK` で除外（失敗しても続行） |
| 画面キャプチャ | `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)` を試行（Win10 2004+、失敗は無視） |

#### 設定

ヘッダーの **シールド設定アイコン**（`Shield`。ツールチップ「シールド設定」）から変更できます。値は `config.json` に保存されます。

| 項目 | `config.json` | 既定 |
|---|---|---|
| ホットキー | `shield_hotkey` | `Ctrl+Shift+P`（修飾キー + 英数字 / F1〜F12） |
| 解除の長押し時間 | `shield_hold_ms` | `1000`（500 / 1000 / 2000） |
| 起動直後から隠す | `shield_start_hidden` | `false` |
| シールド中の見た目 | `shield_appearance` | `files`（`files` = ファイル名リスト / `plain` = 無地） |

#### 限界（重要）

- **物理的に画面を見られたら防げません。** これは「一瞬隠す」ための機能です
- `WDA_EXCLUDEFROMCAPTURE` は **Windows 10 2004 以降のみ**。古い環境・リモートセッション・
  DWM 無効時は効かないことがあります（失敗してもアプリは落ちません）
- グローバルホットキーが他アプリと衝突する場合は「シールド設定」で変更してください
- グローバルホットキー（非アクティブ時）、`DWMWA_EXCLUDED_FROM_PEEK`、
  `WDA_EXCLUDEFROMCAPTURE` は**実機での手動確認が必要**です。CI では
  `cargo check / test / clippy / fmt`、`npm run build / typecheck`、headless Chrome の
  `<img>` 0 件確認までを行います

#### 確認用

- `?bench=200&shield=1` … 200 件の合成データでシールド中の画面から開く（`plain` / `files` も可）
- `npm run test:unit` … ホットキー / Esc の長押し遷移、動画の pause + mute（DOM モック）、
  設定の丸めと `config.json` 往復に加え、選択・並び替え・絞り込み・表示モード・音量・Undo の
  純粋ロジック（[docs/testing.md](./docs/testing.md)）
- `cargo test` … `config.json` の実ファイル保存 / 復元と、ホットキー文字列のパース
- `cd src-tauri && cargo run --features dev-tools --bin smoke -- --json` … GUI を出さない起動スモーク

## 設定画面（#8）

ヘッダー右の **設定アイコン**（`Settings2`。ツールチップ「設定」）から開きます
（`?settings=1` でも起動時に開けます。headless 検証用）。
`App.tsx` への変更は `<SettingsDialog />` の 1 行だけで、設定は独立コンポーネントです。
設定の正は `%APPDATA%\works-browser\config.json`。ルート（パス・深さ・有効 / 無効）は
索引 DB が正です（走査対象そのもので、設定ファイルには複製しません）。

| セクション | できること | 反映 |
|---|---|---|
| 走査ルート | 追加（#25 の OS フォルダダイアログ、複数可）、深さ、有効 / 無効、削除 | 追加・有効 / 無効・削除は即時。深さは次回の走査から |
| 除外パターン | 1 行 1 glob。既定値に戻す / すべてクリア | 次回の走査から |
| ffmpeg | 自動検出結果（パス・発見元・`-version`）の表示、手動指定と存在チェック | 次回のサムネイル生成から |
| サムネイル | 品質（1–100）、キャッシュ上限（MB、0 = 無制限）、使用量、キャッシュ削除 | 品質は保存後、上限は生成のたびに古い順へ整理 |
| ComfyUI | URL・workflows フォルダ・接続確認（`GET /system_stats`） | 保存後すぐ（#73） |
| 動作 | 起動時に隠す（#22）、音量を保存する（既定オフ = 毎回ミュート） | 次回起動 / 次回再生から |

- **ルートの有効 / 無効**: 無効にすると作品・ファイル・集計から即座に消えます（索引は残るので
  有効に戻せば再走査なしで戻ります）。削除は作品・ファイル・走査履歴も消します。
- **除外パターン**: `*` は任意の文字列（区切り文字も含む）、`?` は 1 文字。ファイル名と
  ルートからの相対パスの両方に当てます。既定は `node_modules` / `__pycache__` / `.*`。
  空にすると何も除外しません（ドット始まりのフォルダも走査します）。
- **キャッシュ削除**: サムネイルの WebP と DB の参照を消します。次に必要になった分だけ
  再生成されます。**実データ（作品フォルダ）には触れません。**
- **音量**: 既定は毎回ミュート・音量 0。オフのままなら保存もしません。

| キー | 既定 | 説明 |
|---|---|---|

### 設定画面の Tauri コマンド（#8）

| コマンド | 説明 |
|---|---|
| `get_settings()` | `config.json` + ルート一覧 + 実効サムネイル設定 + キャッシュ使用量 + ffmpeg 検出 |
| `update_settings(patch)` | 差分保存（除外・ffmpeg・品質・上限・動作・表示）。保存後の全体を返す |
| `clear_thumb_cache()` | キャッシュを削除（DB の参照も外す）。削除件数・解放バイト・使用量を返す |
| `ffmpeg_probe(path?)` | パス指定なら存在 + `-version` を確認、省略なら自動検出 |
| `update_root(root_id, depth?, enabled?)` | 深さ・有効 / 無効の更新 |
| `delete_root(root_id)` | ルートと作品・ファイル・走査履歴を削除 |

検証は GUI を起動せず、`cargo test`（config の保存 / 破損時の `.bak` 退避・除外パターンの
走査反映・キャッシュ削除 / 上限整理・ルート無効化）、`npm run build` / `typecheck`、
headless Chrome（`?settings=1`）で行います。設計の詳細は
[docs/settings-design.md](./docs/settings-design.md) を参照してください。

### 作品詳細ギャラリーとライトボックス（#5）

作品カード（またはファイルモードのファイル）を開くと、**代表 1 枚ではなく作品内の全ファイル**を
その場で閲覧できます。画像と動画が混在したまま並び、長さ・サイズ・更新日・種類（メタ 2 行目）が出ます。

#### 画面

| 場所 | 内容 |
|---|---|
| ヘッダ（3 層） | 左上の `←`（ツールチップ `ライブラリへ戻る（Esc）`）/ 題名 32px・1〜2 行 / メタ 1 行 `24 ファイル · 100.7 MB · 2026/11/25` / 評価の独立行（星 + `3 / 5` または `未評価`。#99） |
| 補助情報 | お気に入り・タグ・開封数・ルート名は評価行の右側（12px secondary） |
| ツールバー（1 段） | 種類はセグメント（すべて / 動画 / 画像）、並びはメニュー（名前 / 更新日 / サイズ / 長さ）、昇降はアイコントグル。右端に `N ファイル` と `サムネ表示`（#99） |
| 本文 | 全ファイルのサムネイルグリッド（`@tanstack/react-virtual` の仮想スクロール）。**4:3**・角丸 12・名前 1 行・メタ 2 行（#98 のカード規則） |
| 右上 | **開く**（選択中、なければ先頭のファイルをライトボックスで開く）/ **フォルダ**（エクスプローラで作品フォルダを開く）/ `⋯` メニュー（選択ファイルを表示・この作品をゴミ箱へ） |
| 選択バー | チェックボックス + `Ctrl` / `Shift` / 矩形ドラッグでファイル単位に選択。件数・合計サイズ・**比較**・**削除**・選択解除 |

- 題名は 2 行まで（`line-clamp-2`）。削除・移動などの頻度の低い操作は右上の `⋯` にまとめ、
  メニューは Escape / 外側クリックで閉じてトリガーへフォーカスを戻す
- ページングは `get_work_files(work_id, limit, offset, sort, kind, query)` で **300 件ずつ**。
  1,000 ファイルでも 4 往復で読み切れ、スクロールは可視行だけを描画する
- サムネイルはカード最小幅 148 / 196 / 268px（小 / 中 / 大）。列数はウィンドウ幅に追従し、
  サムネイルの高さは列幅の 3/4（4:3）で、仮想スクロールの行高と一致させる
- 動画サムネには前回の再生位置があると `▶ 0:42` の続きバッジが出る
- **サムネ非表示モード**中はこの画面も画像を 1 枚も読まず（`<img>` / 画像リクエスト 0 件）、
  種類アイコンだけのグリッドになります。`Enter` で開けばライトボックスで閲覧できます
- ファイルモードから開いた場合は、そのファイルが見つかるまでページを足して
  ライトボックスを直接開く

#### ライトボックス / プレイヤー

| 操作 | キー |
|---|---|
| 前後のファイル | 画像: `←` / `→`、動画: `Shift+←` / `Shift+→` |
| 動画の ±5 秒 | `←` / `→` |
| 再生 / 停止 | `Space` |
| 画像のズーム | ホイール（20%〜800%、ドラッグで移動）、`0` で原寸（100%） |
| 全画面 | `F` |
| 閉じる | `Esc` |

- 動画はシークバー・音量・ミュート・速度（0.5 / 0.75 / 1 / 1.25 / 1.5 / 2x）をライトボックス内に持つ
- 画像は現在 ±3 枚を先読みする（`new Image()`。実アプリのみ）
- 再生位置は **5 秒ごと / 一時停止 / シーク / 閉じる**時に SQLite の `file_positions` へ保存し、
  次回開いたとき **3 秒以上**なら「続きから」で復元する（終端 2 秒前まで見たものは最初から）
- WebView2 が再生できるのは mp4（H.264 / AAC）や webm など。mkv / avi などは
  「この動画を再生できません」と案内し、エクスプローラへの導線を残す
- **シークバー上でフレームプレビュー（#47）**: シークバー上でマウスを動かすと、
  **150ms** 止まった地点のフレームを幅 160px で時刻付き表示する（YouTube 相当）。
  マウスが外れる / 再生開始 / ファイル切替で消え、キーボードのシークでは出ない。
  プレビューは本体とは別の `muted` 固定 `<video>` と **1 枚を使い回す canvas** で作り、
  本体の再生位置・再生状態には触れない。デコードできない動画ではプレビューだけ出さず、
  本体の再生は止めない（描画は `webp` quality 0.7 の data URL）

#### メディア配信（Range）

動画・原寸画像は `asset` protocol ではなく、専用スキーム **`wbm`** で配信します。

- URL は `convertFileSrc(String(files.id), "wbm")`（Windows では `http://wbm.localhost/<id>`）。
  UI はパスではなく **`files.id` だけ**を渡し、Rust が DB から実パスを引く
- `Range: bytes=start-end` / `bytes=start-` / `bytes=-suffix` に対応（206 / 416）。
  1 応答は動画 8MB・画像 32MB までに区切り、続きはプレイヤーが Range で取りに来る
- 10GB の動画でもファイル全体をメモリに読まない。`Content-Type` は拡張子から決定

### 比較ビューとキーボード操作（#71）

生成違いを見比べるための比較ビューと、一覧・詳細で使えるキーボード操作です。

#### 比較ビュー

| 場所 | 起動 |
|---|---|
| ライブラリ（作品モード） | チェックボックスで **2〜4 作品**を選び、選択バーの **「比較」** |
| ライブラリ（ファイルモード） | チェックボックスで **2〜4 ファイル**を選び、**「比較」** |
| 作品詳細 | チェックボックスで **2〜4 ファイル**を選び、選択バーの **「比較」** |

- レイアウトは枚数で切り替わります。**2 枚** = 左右、**3 枚** = 左 1 + 右 2、
  **4 枚** = 2×2（`src/lib/compare.ts` の `compareLayout`）
- **ズームとパンは 1 つの状態を共有**します。どこか 1 枚を拡大すると、全部が同じ倍率・
  同じ相対位置になります（ホイールで 20%〜800%、拡大中はドラッグで移動、
  ダブルクリックで 1↔2、`0` で原寸）
- 作品モードから起動した場合は、各作品の**カバー**を比較します（動画を含む作品は
  カバーの先頭フレーム）。ファイルモード / 作品詳細からは選択したファイルそのもの
- **動画は先頭フレーム（サムネイル）で静止**して並び、各セルの **「再生」** で
  その 1 本だけを個別に再生 / 停止できます（`Space` はフォーカス中の動画）
- シールド中（#22）は比較ビューの中身を DOM に残しません（`<img>` 0 件）。
  ベンチモードでは実メディアが無いため、サムネイルだけを「先頭フレーム」として表示します
- 比較ビューの `Esc` は詳細画面の「戻る」より先に閉じます

#### 差分タブ（#74）

比較ビューの上部にある **「差分」** タブで、2 枚の生成設定（`get_generation_meta` の
prompt / negative / model / LoRA / steps / sampler / cfg / seed / size）を比べられます。

| 項目 | 表示 |
|---|---|
| プロンプト / ネガティブ | 単語単位の差分。日本語は 1 文字単位。1 枚目の削除は**赤**、2 枚目の追加は**緑** |
| モデル / Steps / サンプラー / CFG / Seed / サイズ | 左右に値を並べ、違う項目だけ展開 |
| LoRA | セット差（**共通** / **1 のみ（削除）** / **2 のみ（追加）**） |

- 差分は **2 枚のときだけ**。3〜4 枚ではタブを無効にし「2枚で比較してください」と案内します
- **一致した項目は 1 行**（「一致（N）: モデル / Steps / …」）にまとめて薄く表示し、
  差分のある項目だけを展開します
- **seed 以外がすべて同じ**（seed は両方にあり、値が違う）ときは **「seed 違い」** バッジを出します
- 片方に生成情報が無い場合は「生成情報なし（項目が空なのとは別です）」と明示します。
  項目が空のときは `（なし）` / `（空）` を区別して表示します
- 差分の計算は `src/lib/promptDiff.ts` の純関数（LCS のトークン差分・LoRA の集合差）に切り出し、
  UI（`src/library/MetaDiffPanel.tsx`）は結果を描画するだけです
- テストは `tests/prompt-diff.test.ts`（完全一致 / 1 項目だけ違う / prompt の語順 / 片方 null /
  LoRA の追加と削除 / 空文字と null の区別 / 日本語・記号）と
  `tests/prompt-diff-view.test.tsx`（タブの有効 / 無効・seed バッジ・生成情報なし・Esc）

#### ショートカット（一覧・詳細）

| 操作 | 動作 |
|---|---|
| `j` / `k` | 次 / 前のカード・ファイルへフォーカス（仮想スクロールの末尾では次ページを読み込み） |
| `1`〜`5` | フォーカス中の作品を評価（ライブラリは 1〜4 件選択中ならその全部、詳細は開いている作品） |
| `0` | 評価を未評価に戻す |
| `F` | お気に入りを切り替え |
| `Space` | フォーカス中の動画を開いて再生（詳細 / ファイルモード）。比較ビュー内では個別動画の再生 / 停止 |
| `Enter` | フォーカス中の作品・ファイルを詳細（ファイルはライトボックス）で開く |
| `Esc` | 比較ビュー / 作品詳細を閉じる（ライブラリでは選択解除） |
| `?` | ショートカット一覧を開く（#82。Esc で閉じる） |

- **入力欄・選択欄・contenteditable にフォーカスがあるときは無効**です（`/` 検索で
  入力中に `1` を押しても評価されません）
- `Ctrl` / `Alt` / `Meta` 付きのキーは一覧・詳細のキー操作では扱いません
  （`Ctrl+1..9` はルート切替、`Alt+1..3` は表示モード、`Ctrl+Shift+P` はシールドが使います）。
  `/`（検索）・`Delete`（削除）とも競合しません
- 評価・お気に入りは保存後すぐに反映されます。詳細画面の星 / ハートも
  `works-browser:mark-changed` イベントで読み直します
- 判定の単体テストは `tests/shortcuts.test.ts`、レイアウトとズームは
  `tests/compare.test.ts`、同期ズームと `Esc` は `tests/compare-view.test.tsx`

### タグ・評価・開封回数（#6）

作品を分類し、よく見るものを上に出すための機能です。タグ・評価・開封回数は
**索引 DB（スキーマ v5）** に入り、フォルダを再走査しても残ります。

#### タグ

| 場所 | 操作 |
|---|---|
| ライブラリ上部の「タグ」チップ | 1 クリックで絞り込み（もう一度押すと解除）。作品数はツールチップに表示 |
| 作品詳細の「タグ」ボタン | ダイアログで ON / OFF。チェックした瞬間に保存 |
| 選択バーの「タグ」 | 選んだ作品すべてに同じタグを付ける |
| ダイアログ下部の「新規」 | 名前（40 文字まで）+ `<input type="color">` で色を選んで作成 |
| 各行のゴミ箱 | タグ自体を削除（全作品から外れる） |

- タグ名は大文字小文字を区別しません。同じ名前で作り直すと色だけ更新されます
- `work_tags` は `works` / `tags` への外部キーで、`ON DELETE CASCADE` が効きます。
  索引から作品が消えたとき・タグを消したときに付与だけが消えます
- 再走査は `works` を upsert するだけなので、タグは付いたままです
  （`cargo test` の `rescan_keeps_tags_marks_and_open_counts`）

#### お気に入り・5 段階評価

- 作品詳細のハート / 星（1〜5）を押した瞬間に保存します。同じ星をもう一度押すと未評価に戻ります
- ライブラリの「フィルタ」ポップオーバーで「お気に入り」/「評価」を絞り込み、選択バーの「評価」で一括設定できます
- README の `find_works` は `favorite` / `min_rating` も受け取ります（UI はお気に入りのみ使用）

#### 開封回数と「最近見た」「よく見る」

- **作品詳細を開くたび**に `record_open(work_id)` を呼び、`marks.open_count += 1` と
  `last_opened_at` を更新します（OS は開封回数を残さないためアプリ側で記録）
- 並び替えに **最近見た**（`last_opened`）/ **よく見る**（`open_count`）を追加しました。
  未開封の作品は末尾へ送ります
- 詳細のヘッダに「開封 N 回」を表示します

#### 確認用

- `?bench=60` … 合成 60 作品でタグ・評価・開封回数を確認（ベンチ実装はメモリ内）
- `npm run test:unit` / `npm run build` / headless Chrome
  （`D:\Projects\works-browser-6\verify-tags.mjs`。詳細 → タグ作成 → フィルタ → 並び替え）
- `cargo test` … タグ CRUD / 付与 / フィルタ / open_count 加算 / 再走査後もタグが残る

### スマートフォルダ（保存検索・#69）

いまの絞り込み条件を名前付きで保存し、サイドバーから 1 クリックで呼び出します。
条件は **索引 DB（スキーマ v10）** の `smart_folders` に入ります（作品そのものは保存しません）。

#### 保存する条件

| 項目 | JSON のキー |
|---|---|
| 検索語（タイトル・パス） | `search` |
| 種類（すべて / 動画あり / 画像のみ） | `kind` |
| ルート | `rootId` |
| タグ | `tagId` |
| 最低評価（★3〜★5） | `minRating` |
| お気に入りのみ | `favorite` |
| 検索語を生成情報にも当てる | `metaSearch` |
| 並び順 | `sort` |
| 昇順 / 降順 | `dir` |

#### 使い方

| 場所 | 操作 |
|---|---|
| サイドバー「スマートフォルダ」の **＋** | いまの条件に名前を付けて保存（Enter で確定、Esc で取り消し） |
| 保存した行をクリック | 条件を適用。完全に同じ条件のときだけ行が強調されます |
| 行の「…」→ 名前を変更 | その場で入力欄に切り替わります（40 文字まで） |
| 行の「…」→ 削除 | 保存した条件だけを削除（作品・ファイルは消えません） |

- 件数は新しい集計クエリを作らず、適用中の `find_works` / `find_files` の `total` を
  そのまま表示します（サイドバーの適用中行と、上部の「N 作品」）
- 同じ名前（大文字小文字を無視）で保存すると、並び順と作成日時を保ったまま条件だけ更新します

#### 戻る / 進む（#33）

画面階層は `src/lib/useNavStack.ts` の履歴スタックが唯一の状態です
（`library` → `work` → `lightbox`）。

- カードクリックで詳細へ **push**、ファイルクリックでライトボックスへ **push**
- 戻るは 1 段ずつ pop。**ライブラリより前には戻りません**（履歴が空なら何もしない）
- ライトボックスで `Esc` を押したときも、戻ると同じく詳細へ 1 段戻ります
- 詳細 → 戻る でライブラリへ戻ると、**離脱時のスクロール位置・選択・絞り込み**を復元します（#120）
- 設定 / ルート管理などのダイアログが開いている間は、戻るが**ダイアログを閉じる**のを優先します
- マウスのサイドボタンは WebView2（Chromium）が `mousedown` の `button === 3`（戻る）/
  `4`（進む）として通知するため、`window` で購読して `preventDefault()` しています
  （`auxclick` は二重発火防止のため購読しません）。サイドボタンを取得できない
  マウス / 環境では `Alt+←` / `Alt+→` で同じ操作ができます
- 履歴スタックの単体テストは `tests/nav-stack.test.ts`（push / back / forward、空スタック、
  ダイアログ優先）。絞り込みの復元は `tests/library-filter-restore.test.tsx`（#120）

### 作品の単位（深さ）

ルートごとに、どの階層を「作品」とするかを選べます。

| 深さ | 例 | 作品 |
|---:|---|---|
| `1`（既定） | `output\series1495\001.png` | `series1495` |
| `2` | `Media\\Gamma\作品\サブ\001.mp4` | `作品\サブ` |
| `0` | `ルート直下の 001.png` | ルート自体（フラット） |

深さ `1` / `2` では、指定より浅い位置にあるファイル（例: ルート直下に置かれた動画）は、
**存在する階層まで**（ルート直下ならルート自身）の作品にまとめます。件数が Explorer とずれません。
深さ `0` は設計どおりルート直下のファイルだけを 1 作品にまとめ、サブフォルダは対象外です。

### 対応拡張子

| 種別 | 拡張子 |
|---|---|
| 画像 | `jpg` `jpeg` `png` `webp` `gif` `bmp` `avif` |
| 動画 | `mp4` `mkv` `mov` `avi` `webm` `m4v` `wmv` `flv` |

上記以外（`.txt`、`.blend`、サイドカーなど）は索引に載せません。除外は既定で
`.` 始まり、`node_modules`、`__pycache__` です。設定画面の「除外パターン」（#8）で
1 行 1 glob を追加・変更できます。

**`.ts` は既定では索引しません**（#39）。TypeScript のソースを MPEG-TS と誤認して
動画扱いし、サムネイル生成が失敗するためです。MPEG-TS を動画として索引したい場合だけ、
`config.json` の `index_mpeg_ts` を `true` にしてください（既定 `false`）。
有効にすると `.ts` も動画として索引します。無効に戻して再走査すると、既存の `.ts` の
レコードと、それだけになっていた作品は自動的に削除されます。

`avif` は索引に載せますが、サムネイル生成は未対応です（軽量なデコーダが無く、
ビルドが重くなるため）。サムネイルはプレースホルダになります。

### フォルダ監視（#7）

アプリ起動中は、`enabled = 1` のルートを `notify` で監視し、Explorer での追加・削除を
再起動なしで索引へ反映します（Issue #7）。実装は `src-tauri/src/index/watch.rs` です。

- **追加 / 更新**: `files` へ UPSERT し、サムネイルを生成待ちに戻します
  （`thumb_path` を NULL にするので、次回の `generate_thumbs` が拾います）。
- **削除**: `files` から削除し、空になった作品とサムネイルキャッシュも削除します。
- **リネーム**: 「旧パスの削除 + 新パスの追加」として扱います（DB の `files.id` は変わってよい）。
- **デバウンス**: 1 秒。コピー中の大量イベントを 1 バッチにまとめます。
- **上限**: 1 バッチ 4,000 イベント、ディレクトリ 1 件あたり 5,000 ファイルを超えたら
  差分適用をやめてそのルートを再走査します（1 万件コピーでも暴走しません）。
- **起動時**: 設定 `watch_enabled` が `true`（既定）なら自動で開始します。

#### 監視しないもの

| 対象 | 既定 |
|---|---|
| 拡張子 `.tmp` / `.part` | 常に除外（書きかけファイル） |
| ファイル名 `Thumbs.db` / `.DS_Store` | 常に除外 |
| `.` 始まり / `node_modules` / `__pycache__` のディレクトリ | 走査と同じく除外 |
| ネットワークドライブ（`L:\` / UNC） | 監視しない |
| 設定 `watch_exclude` の glob | ファイル名とルート相対パスに一致したら除外 |

glob は `*`（階層内の任意文字）、`**`（階層をまたぐ）、`?`（1 文字）に対応し、
Windows なので大文字小文字を無視します。例: `["*.psd", "cache/**"]`。

#### 無効化・設定

`config.json` の次の項目で制御します。`save_config` を呼ぶと即時に再起動します。

```json
{
  "watch_enabled": false,
  "watch_exclude": ["*.psd", "cache/**"],
  "watch_network_drives": true
}
```

- `watch_enabled: false` … 監視を止める（索引はそのまま。手動走査は使える）
- `watch_network_drives: true` … `L:\` などのネットワークドライブも監視する

#### Tauri API

- `watch_status()` … `{ enabled, roots: [{ root_id, enabled, path }] }`。
  `enabled` は設定、`roots[].enabled` は実際に監視を開始できたか。
- イベント `watch://changed` … `{ root_id, added, removed, rescan }`。
  UI はこれを受けて一覧を再取得すればよい（`added` は更新も含む目安の件数）。
- `watch_pending()` / `clear_watch_pending(root_id)` … ルート別の新着件数（メモリのみ・永続化しない）。
- サイドバーのルート行には、監視で増えた件数が `+N` の新着バッジとして出て、そのルートを開くと消えます（#63）。

## サムネイル

グリッド表示用のサムネイルを Rust 側で生成し、`%LOCALAPPDATA%\works-browser\thumbs` に
WebP でキャッシュします（Issue #3）。

- **画像**: `image` で長辺 **512px** に縮小し、品質 **75** の WebP にエンコード。
  EXIF の向き（Orientation）を反映し、透過 PNG のアルファも保持します。
- **動画**: ffmpeg で尺の **10%** 地点のフレームを 1 枚抜き出して同じく WebP 化。
  失敗したら **1 秒地点** → 先頭フレームの順に再試行し、それでも駄目なら
  プレースホルダ画像を書きます（アプリは落ちません）。
- **並列**: rayon の専用プールで、既定は **CPU コア数 − 2**（上限 32）。ffmpeg は
  `-threads 1` で動かすので、コア数に応じてプロセスを並べる方が動画が速い。
  `generate_thumbs(limit)` は未生成の分だけを DB から拾って処理するので、UI は
  スクロールに合わせて必要な分だけ遅延生成できます。
- **無効化**: 元ファイルの mtime / size が変わると再生成します（`files.thumb_mtime` /
  `files.thumb_bytes` と比較）。キャッシュは一時ファイル → `rename` で書くため、
  生成中にアプリが落ちても壊れた WebP は残りません。
- **作品カバー**: 「最初の動画 → 最初の画像 → 先頭ファイル」の順で自動選択し、
  `works.cover_file_id` に保存します。`list_works` の `cover_thumb_path`、
  `get_work` の `files[].thumb_path` にキャッシュのフルパスが入ります。

### 必要なもの（ffmpeg）

| 対象 | 必要 |
|---|---|
| 画像サムネイル | 不要（`image` + `webp` crate を同梱） |
| 動画サムネイル | ffmpeg（同梱 sidecar / PATH / 下記の既定候補のいずれか） |

ffmpeg は次の順で探します。見つからない場合、動画はプレースホルダになります。

1. 設定画面の「ffmpeg パス」（`config.json` の `ffmpeg_path`。旧 `thumbs.ffmpeg_path`）／環境変数 `WORKS_BROWSER_FFMPEG`
2. アプリの exe と同じフォルダの `ffmpeg.exe`（Tauri sidecar。`bundle.externalBin`）
3. `PATH`
4. `D:\Projects\08_media_tools\media-tools\bin\ffmpeg.exe`

### キャッシュの場所

| 項目 | パス |
|---|---|
| サムネイル | `%LOCALAPPDATA%\works-browser\thumbs\<sha1>.webp` |
| 任意 | 環境変数 `WORKS_BROWSER_THUMBS_DIR` で上書き（テスト・計測用） |

ファイル名は **ルートの実体パス + ルートからの相対パス** の SHA-1 です
（仕様の `<sha1(rel_path)>` だけだと、別ルートに同じ相対パスのファイルがあると
別の絵が出るため、ルートも混ぜています）。ルートを移動すると作り直しになります。

### 品質・並列数の変更

設定画面（#8）で品質・キャッシュ上限を変更できます。値は `config.json` が正で、
#3 の `meta` テーブルにも同じ品質を同期します（`update_thumb_settings` も引き続き使えます。
範囲外は丸めます）。キャッシュ上限を超えた分は生成のたびに古い順に削除されます。

| キー | 既定 | 範囲 |
|---|---:|---:|
| `max_edge` | 512 | 64–1024 |
| `quality` | 75 | 1–100 |
| `parallelism` | 8 | 1–16 |
| `ffmpeg_path` | （未設定） | 空文字で既定探索に戻す |

品質を変えたときは `reset_thumbs()` でキャッシュを捨ててから生成し直してください。

### サムネイル関連の Tauri コマンド

| コマンド | 説明 |
|---|---|
| `generate_thumbs(limit = 500, force = false)` | 未生成を最大 `limit` 枚生成。進捗は `thumbs://progress`（done / total） |
| `thumb_queue_size()` | 生成待ちの件数 |
| `thumb_status()` | 残り・生成済み・設定・ffmpeg の探索結果 |
| `cancel_thumbs()` | 実行中の生成をキャンセル（中断可能） |
| `update_thumb_settings({ max_edge, quality, parallelism, ffmpeg_path })` | 設定を保存して実効値を返す |
| `reset_thumbs(delete_files = true)` | サムネイルの状態を捨てて作り直せるようにする |

UI から使う進捗イベントは `thumbs://progress`（`{ done, total }`）です。
`src/components/ThumbStatus.tsx` は shadcn の `Progress` / `Badge` / `Button` で作り直し、
`App.tsx` のヘッダーにマウントしました。

- 未生成が残っていれば `generate_thumbs(500)` を**1 回だけ**キックする（`kicked` ref で抑止）
- 生成が終わったら `refreshToken` を進めて `find_works` を読み直し、`cover_thumb` を反映する
- ヘッダーの目アイコン（`Ctrl+Shift+H`）でサムネ非表示にすると、`useThumbnailVisible` 経由で
  `convertFileSrc` を呼ばず、`thumbs://progress` の購読と自動生成も止める
- カバーは `cover_thumb` の絶対パスを asset protocol で表示する
  （`tauri.conf.json` の scope は `%LOCALAPPDATA%\works-browser\thumbs/**` のみ）

| NSIS インストーラ | `src-tauri/target/release/bundle/nsis/works-browser_x.y.z_x64-setup.exe` | ダブルクリックでインストール（管理者権限不要・ユーザー単位） |

GitHub Releases には NSIS / MSI が添付されます。portable 版は Actions の
`installers-v*` artifact（保持 14 日）に入る `works-browser.exe` を使います。

### インストールせずに使う（portable）

1. `works-browser.exe` を好きなフォルダ（例: `D:\Projects\works-browser\`）に置く
2. 必要なら `ffmpeg.exe` を同じフォルダに置く（動画サムネイル用。#3 の探索順で 2 番目に使われる）
3. `works-browser.exe` をダブルクリック

```
D:\Projects\works-browser\
  works-browser.exe
  ffmpeg.exe          ← 任意
```

- **WebView2 Runtime が必要**です。Windows 11 は標準搭載。Windows 10 は
  [WebView2 Evergreen Bootstrapper](https://developer.microsoft.com/microsoft-edge/webview2/) を導入してください。
- 設定・索引は `%APPDATA%\works-browser\`（開発ビルドはリポジトリの `.cache\`）に保存されるため、
  exe を別のフォルダへ移してもデータは引き継がれます（フォルダを移すだけで引っ越し完了）。
- アンインストールはフォルダごと削除するだけです。

### ffmpeg の置き方（ビルドする場合）

ffmpeg はリポジトリにコミットしていません。ビルド前に sidecar 用の名前で配置します。

```powershell
# 既存の ffmpeg（D:\Projects\08_media_tools\media-tools\bin\ffmpeg.exe）をコピー
powershell -ExecutionPolicy Bypass -File scripts/fetch-ffmpeg.ps1

# 別の ffmpeg を使う場合
powershell -ExecutionPolicy Bypass -File scripts/fetch-ffmpeg.ps1 -Source C:\path\to\ffmpeg.exe
```

配置先は `src-tauri/binaries/ffmpeg-x86_64-pc-windows-msvc.exe`（`.gitignore` 済み）。
無いと Rust 側のビルドが失敗します。詳細とライセンスの注意は [docs/build.md](./docs/build.md)。

## サムネイル表示の方針

- **起動のたびにサムネイルは非表示から始まります**（前回「表示」にしていても、次回起動時は非表示）
- 一時的に表示したいときは目のアイコンで切り替える（セッション内のみ）
- 非表示中は画像リクエストを一切出さない
- 非表示中に「このファイルだけ」「この作品のサムネイルだけ」を一時表示できる
  （全体トグルを切り替えるとリセット・非永続）
- 切替 UI は共通の `ThumbnailToggle`。ヘッダーは `compact`（アイコンのみ）、
  ライブラリ / ファイル / タイムライン / 作品詳細のツールバーは `labeled`
  （`Eye` / `EyeOff` + 「サムネ」）で、`aria-pressed` は表示中かどうか（#121）
